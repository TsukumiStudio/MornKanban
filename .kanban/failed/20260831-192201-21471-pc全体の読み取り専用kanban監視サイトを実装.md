## Task

# 目的
このPC上の複数プロジェクトにある MornKanban の盤面・カード履歴・実行状態を、localhost のWebサイトで横断的に閲覧できる監視サーバーを実装する。閲覧専用であり、このサイトから指示、カード追加、状態変更、プロセス操作は一切できないこと。

# 前提
- main には VERSION/CLI更新管理（commit 204217e）がマージ済み。これを土台にする。
- MornKanban本体は bash 3.2 互換、Web側は python3標準ライブラリのみ（pip不可）、フロントは素のHTML/CSS/JS。
- 既存の単一プロジェクトGUI、setup、version/install/update/uninstall、秘書スキル、kanban run の挙動を壊さない。
- 通常ワーカーなのでブラウザ自動操作は使わず、HTTP/CLIテストで検証する。

# 必須仕様
## 複数プロジェクトの発見
- 既定では ~/git など明示的な探索ルート配下から `.kanban` を持つプロジェクトだけを安全に発見する。ファイルシステム全体は探索しない。
- 探索ルートはユーザー設定で追加・変更できる。設定保存先と形式をREADMEに明記する。テストではHOMEと設定先を差し替え可能にする。
- symlink loopを回避し、各プロジェクト内の `.kanban/wt` 以下を別プロジェクトとして列挙しない。realpathで重複排除する。

## 読み取り専用 localhost サーバー
- 既定bindは必ず 127.0.0.1。外部公開は既定にしない。
- GET/HEADのみ提供し、POST/PUT/PATCH/DELETE等は405で拒否する。盤面やプロセスを書き換えるAPI・UIを実装しない。
- realpath allowlistでdirectory traversalと未登録プロジェクトへのアクセスを防ぐ。HTML出力をescapeし、静的ファイル/APIパスも安全に扱う。
- CLIから foreground 起動できる（例: `kanban monitor`）。PC常駐用途としてmacOSユーザーLaunchAgentの install/start/stop/status/uninstall 相当も提供する。ただし既存の `kanban install/update/uninstall` と名前・責務が衝突しない明確なサブコマンド構造にする。
- 常駐管理は冪等で、MornKanban以外のLaunchAgentやファイルを削除しない。実HOMEを汚さずテスト可能にする。

## 表示
- プロジェクト一覧と各 todo/doing/review/done/failed 件数。
- dispatcher の running/stopped 状態（`.kanban/.lock` のPIDが実在するかを確認し、stale lockをrunning扱いしない）。
- プロジェクト別のKanban列、カードのfrontmatter/本文/History（worker/reviewログを含む）。
- 全プロジェクト横断の最近の活動。
- 定期pollingまたは手動更新と、最終更新時刻。読み込み失敗はサイト全体を落とさずプロジェクト単位で表示する。
- 見やすいレスポンシブUI。操作ボタンや編集フォームは置かない。

# 実装・配置
- 既存構成を調査し、kanban.sh、monitor用Python/HTML/CSS/JS、setup/配布対象、README、必要ならgui/VERIFY.md等を整合させる。
- インストール・アップデート後もmonitor資材を正しいリポジトリ相対位置から解決できること。
- バージョン管理規約に従い、配布物の機能追加としてVERSIONを適切に更新する。
- 現在main checkoutに残る完了カード履歴はユーザーの盤面データなので削除・上書きしない。

- `.kanban/wt`除外、symlink loop/重複排除、path traversal拒否、未許可path拒否、HTML escape、書き込みHTTPメソッド405を検証する。
- live PID lockとstale lockの判定を検証する。
- bind既定値が127.0.0.1であること、foregroundサーバーの起動/終了、monitor用CLIとLaunchAgent lifecycleを一時HOMEで検証する。テスト後にプロセスを必ず終了する。
