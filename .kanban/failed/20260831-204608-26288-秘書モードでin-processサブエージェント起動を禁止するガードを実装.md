## Task

# 問題
MornKanban秘書としてbootstrap済みの対話agentが、カードを1枚も作らず、`kanban-secretary.sh dispatch`も呼ばず、visible Herdr paneを一度も作らないまま、Claude/Codex自身のin-process subagent機能を起動して調査・実装を進める契約違反が実際に発生した。事後に「契約違反だった」と自己申告するだけでは弱く、繰り返される。

# 目的
秘書モードの対話agentを「カード起票とvisible Herdr dispatch専任」に固定する。skill文言だけに依存せず、可能な範囲でsession/pane単位の技術的guardを実装し、Claude CodeのAgent/Task系およびCodexのcollaboration/subagent系を秘書pane内では拒否する。他の通常session、worker、reviewer、resolverでは従来どおり利用可能にし、PC全体を一律禁止しない。

# 絶対契約
- 秘書はimplementation/research/review/fix/verification要求を受けたら、最初の実作業として自己完結cardを作り、`kanban-secretary.sh dispatch`へ渡す。
- 秘書自身はsource調査、実装、検証、review、競合解決をしない。card作成に必要なproject policy/board確認だけ許可する。
- 秘書paneでは組み込み/in-process delegationを使わない。例: Claude CodeのAgent/Task/subagent、Codexの`spawn_agent`/collaboration agent等。workerは必ず`herdr-agent-worker.sh`経由のvisible Herdr paneで起動する。
- accidentalなin-process agent起動を検出した場合は即停止し、その成果をmerge/採用せず、同じ要求をcard化してvisible dispatcherへ回す。

# 技術的guard
- `kanban-secretary.sh bootstrap`で、project root・Herdr pane id・resolved project-specific secretary agent名に紐づくactive secretary marker/registrationをatomicに作成する。終了・再bootstrap・stale pane時のcleanup/更新方法を設計する。
- Claude Code/Codexそれぞれについて、このmachineに導入済みのversionと公式/local docsを調査し、tool hook/policy/managed wrapper等の正式な拒否点を使う。Claude/Codexのprivate fileを雑にpatchしたり、未確認の設定keyを捏造しない。
- tool invocation前hookが使える環境では、現在paneがactive secretary markerと一致し、対象toolがin-process delegationなら明確な理由付きでdenyする。
- guardはproject/pane scopedとし、visible Herdrで起動したworker/reviewer/resolver paneや他projectの通常agentをblockしない。
- setup/install/updateでguard資材と必要なmanaged hookをversioned distributionとして導入・更新する。uninstallはinstaller-managed entryだけを安全に除去し、ユーザー既存hook/configを壊さない。既存設定へ統合する場合はbackup/marker/構造保持を保証する。
- 一方のCLIに正式なpre-tool hookが存在しない場合は、そこで黙って「対応済み」としない。利用可能なsession-scoped enforcement（project instruction、managed policy、wrapper等）を組み合わせ、技術的に防げない残余境界をREADMEとsetup statusに明示する。ただし少なくとも既存skill/contractは強化し、秘書がbuilt-in agentを選ぶ余地のない手順へ固定する。

# 起票先の強制・観測
- guard拒否メッセージは「秘書モードではin-process agentは禁止。`kanban add`→`kanban-secretary.sh dispatch`を使用」と具体的に示す。
- bootstrap/セットアップダッシュボードにguard状態（Claude: enforced/not supported/misconfigured、Codex: 同様）を表示できるようにする。
- 秘書skill、README Dialogue-Agent Contract、`.kanban/KANBAN.md` templateに、禁止対象tool名/概念、allowed action、違反時recoveryを明記する。
- 秘書がcard作成前に実装系agentを起動した事実を、秘密情報を含めずproject-local audit logまたは診断commandで確認できる設計を検討する。ログの無制限増加や会話本文保存は避ける。

# 既存の責務分離との統合
- failed branch `kanban/20260831-194719-16227` にある「秘書をカード起票専任にして競合解決役を導入」の合格済み成果と、現在mainの状態を調査する。使える契約/guard/resolver成果があれば、片側を捨てず正式に統合する。ただしfailed branchを直接破壊・削除しない。

- headless fallback禁止、visible Herdr必須、Claude/Codex backend両対応を維持する。
