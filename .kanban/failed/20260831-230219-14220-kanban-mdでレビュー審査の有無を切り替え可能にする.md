## Task

# 目的
実装iterationを速く回したいprojectでは、各taskごとのreviewer起動・採点・再試行が長すぎる。`.kanban/KANBAN.md` のmachine-readable frontmatterでreview審査を `する / しない` とproject単位に選択できるようにする。

# 設定仕様
- 明確なsettingを追加する。推奨形は `review_enabled: true|false` または同等の分かりやすいboolean。最終名は既存frontmatter parserや用語と整合させ、README/template/helpで統一する。
- 既存projectの互換性のため、setting未指定のdefaultは `true`（従来どおりreview必須）。
- environment overrideも提供し、優先順位を `card明示override > environment > KANBAN.md > built-in true` とする。
- 必要なら `kanban add --review` / `--no-review` のcard単位overrideを追加する。card frontmatterに決定値/overrideを追跡可能に保存し、別machine/dispatcher再起動でも意味が変わらないようにする。
- `reviewer`、`review_model`、`threshold`等の既存設定は削除せず、review_enabled=true時だけ有効。false時はignoredであることをstatus/helpに示す。
- boolean parserは `true/false` を正式値とし、不正値は黙ってtrue/falseへ丸めず明確にerrorにする。互換目的で別表記を受ける場合はdocument/testする。

# review_enabled=true
- 現行どおりworker commit後にreviewerを起動し、score/threshold、rework、max attempts、resolver後の再reviewを適用する。
- visible Herdr reviewer pane、backend/model/permission policy、History記録を維持する。

# review_enabled=false
- workerが正常終了して成果commitを作成したら、reviewer command/paneを一切起動しない。
- score parse、threshold gate、review rework attemptを行わず、merge処理へ直接進む。
- card Historyへ日時付きで `review skipped: review_enabled=false (source: card/env/project/default)` 等を明記し、審査されていない成果だと後から判別できるようにする。架空のscoreを付けない。
- worker failure、commit失敗、merge conflict等は従来どおり適切な状態へ進める。review OFFを成功扱いの隠蔽に使わない。
- resolverがmerge conflictを解消した場合も、review_enabled=falseならresolver後のreviewerを起動せず統合する。trueなら現行どおり再reviewする。
- notification/done/failed、worktree/branch cleanup、dispatcher restart/reclaim、parallelismを壊さない。
- `KANBAN_REVIEW_CMD`が設定されていてもOFFなら呼ばれない。reviewer用token/pane/processを消費しない。

# 表示・UX
- `kanban show`、dispatcher開始log、monitorのproject/card表示、setup/status等の適切な場所で `Review: ON` / `Review: OFF (fast iteration)` を明示する。色だけに依存しない。
- review OFFは速度優先で品質gateを省略すること、worker自身のtest実行まで自動省略する意味ではないことをREADMEに明記する。
- `.kanban/KANBAN.md` templateにsettingと日本語comment/本文説明を追加する。
- 使用例:
  - 安定運用: `review_enabled: true`
  - 高速iteration: `review_enabled: false`
  - 必要なら特定cardだけ `--review` で審査を戻す
- 秘書はsettingを勝手に変更せず、target project policyをそのままcard/dispatcherへ適用する。

# backend/権限・既存機能との統合
- Claude/Codex、worker/reviewer/resolver、visible Herdrの両backendに対応する。
- 進行中のunrestricted permission cardやguard/resolver統合成果と整合させ、review OFF時だけreviewer起動を省略する。worker/resolver権限、秘書guard、project固有secretary名は維持する。
- headless silent fallbackは禁止のまま。reviewを切ったことを理由にworkerを対話秘書内で実行しない。
- VERSIONをsemantic policyに従って更新する。
