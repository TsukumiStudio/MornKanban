## Task

# 目的
現在のMornKanbanセットアップ画面は、環境の状態や操作結果、各コマンドをどこで実行すると何が起こるかが直感的に分かりにくい。既存の対話CLI一本化という方針は維持しつつ、ターミナル内でグラフィカルかつ説明的なセットアップダッシュボードへ改善する。

# UX要件
## 状況の可視化
- 起動直後に「MornKanbanの現在状態」を一画面で把握できるようにする。
- 少なくとも以下を、色・記号・枠・進捗/状態ラベル等を使って `導入済み / 未導入 / 更新あり / 稼働中 / 停止中 / 要確認` のように表示する:
  - MornKanban本体の場所と現在VERSION
  - CLI (`~/.local/bin/kanban`) の導入状態とリンク先
  - Claude/Codexの `kanban-dispatch` スキル導入状態とversion
  - latest version取得結果とupdate可否
  - monitor LaunchAgentのinstall/running状態、URL、port
  - PC共通project registryの場所と登録project数
  - 現在ディレクトリがprojectか、`.kanban`初期化済みか
- 単なるログ羅列ではなく、セクション、カード風の枠、状態色、短い説明を使う。狭いターミナルでも崩れず、長いpathは安全に折り返す/省略して確認手段を示す。

## 「どこで・何をすると・何が起こるか」
- 画面内に用途別の案内を常時表示する。各項目で以下を明記する:
  1. 実行場所（どのdirectoryからでも / 対象project root / Herdr pane内 / browser）
  2. 実行するcommandまたは操作
  3. 起こること
  4. 変更・作成・削除される場所
  5. 変更されず保持されるもの
- 最低限、次のフローを説明する:
  - 初回install、update、uninstall
  - projectで `kanban init`
  - Herdr内で `$kanban-dispatch 秘書として開始`
  - `kanban projects add/list/remove`
  - `kanban send <alias> <title>` による別projectへの投函
  - `kanban monitor` foreground起動と `http://127.0.0.1:8787/`
  - `kanban monitor daemon install/start/status/stop/uninstall`
- install/update/uninstall等の実行前に「これから変更する対象」を短くプレビューし、確認後に実行する。終了後は成功/失敗、変わったもの、次に行うcommandを表示する。
- uninstall時は、削除するCLI/skillと、削除しないrepository/project boards/registry/monitor設定を特に明確に区別する。

## 操作性・互換性
- 初見の人がREADMEを先に読まなくても、画面だけで導入からproject開始、monitor確認まで進められる日本語表示にする。
- 既存の `y=install / u=uninstall / N=何もしない` と非対話 `kanban-setup.sh {install|update|uninstall|version}`、`kanban {install|update|uninstall|version}` の互換性を壊さない。必要なら対話メニューを拡張するが、既存入力は同じ意味で受理する。
- TTYでは色・Unicode記号等を使ってよいが、非TTY、`NO_COLOR`、狭幅、TERM=dumbではASCII/色なしへ安全にfallbackする。情報を色だけに依存させない。
- ANSI escapeや制御文字をpath/version等の外部値から注入されないようにする。
- bash 3.2互換。追加dependency/pip/npmは不可。
- セットアップ画面から勝手にproject初期化、monitor起動、カード作成をしない。ユーザーが選んだ操作だけを実行する。
- UI変更前に共有 `ui-conventions` の指針を読み、spacing定数、選択/hover相当、状態表示の一貫性を反映する。

# ドキュメント
- READMEのSetup/Versioning/Monitor/Cross-project部分を、セットアップ画面の表現・command・保存場所と一致させる。
- 「どの場所から実行できるか」を曖昧にせず、具体例を掲載する。
- 画面の状態ラベルと実際の判定条件を文書化する。

- TTY/非TTY、NO_COLOR、TERM=dumb、狭いCOLUMNS、長い日本語/pathでレイアウトが壊れず、ANSIなしfallbackが働くことをテストする。
- install/update/uninstallの変更前プレビューと変更後サマリーを検証し、実HOMEを汚さない。
- 既存入力 `y/u/N` と非対話subcommandの回帰テストを維持する。
- 表示されるcommand、path、URLが実装と一致する契約テストを追加する。
- `bash -n kanban.sh kanban-setup.sh kanban-secretary.sh herdr-agent-worker.sh herdr-notify-secretary.sh`、関連Python `py_compile`、既存を含む全テストを実行する。プロセス・LaunchAgent・一時ファイルを必ずcleanupする。
