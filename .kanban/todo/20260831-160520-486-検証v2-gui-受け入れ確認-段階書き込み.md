## Task

## 目的
MornKanban ローカル GUI を起動・操作して受け入れ確認し、レポート `gui/VERIFY.md` を書く。
**コードの修正はしない**。前回の教訓: レポートは最後にまとめて書くのではなく**段階的に書く**こと。

## 手順 (この順序を厳守)
1. まず gui/VERIFY.md を作成し、見出しと「検証開始」を書く (以後、各項目が終わるたびに追記)
2. サーバ起動: MORNKANBAN_GUI_PORT=8777 python3 gui/server.py をバックグラウンド起動 (最後に必ず kill)
3. API 検証 (curl)。各項目の PASS/FAIL とレスポンス断片を**その都度 VERIFY.md に追記**:
   - GET /api/status が deps/herdr_env/repo を含む JSON
   - mkdir -p /tmp/kanban-gui-verify2 のうえ POST /api/projects {"path":"/tmp/kanban-gui-verify2"} → ok:true
   - POST /api/init → /tmp/kanban-gui-verify2/.kanban が生成される
   - GET/PUT /api/policy の往復一致
   - POST /api/card (title=verify, body=test, backend/model/threshold は空文字) → ok:true
   - GET /api/board の states.todo に1枚、GET /api/card?file= が本文を返す
4. ブラウザ検証は**任意扱い**: Chrome 操作ツールを1回だけ呼んでみて、60秒以内に応答が得られなければ
   即座に諦め、VERIFY.md に「ブラウザ検証: ツール利用不可のため未実施 (API 検証で代替)」と追記する。
   使えた場合のみ http://127.0.0.1:8777 を開き、ボード5列・カード追加・モーダル表示を確認して追記
5. /api/secretary と /api/dispatch は実行しない
6. サーバを kill し、VERIFY.md 末尾に総合判定 (PASS/FAIL) を書く

## 完了条件
- gui/VERIFY.md が存在し、手順3の全項目に PASS/FAIL と根拠が書かれ、総合判定があること
- ブラウザ検証は未実施でも、その旨が明記されていれば完了条件を満たす
