## 目的
gui/server.py を「かんばん管理 API」から「環境セットアップ専用 API」へ全面的に書き換える。
既存の board/card/policy/secretary/dispatch 系エンドポイントは**全て削除**する。

## 制約 (既存と同じ)
- python3 標準ライブラリのみ、単一ファイル、ThreadingHTTPServer、127.0.0.1 bind、
  ポートは MORNKANBAN_GUI_PORT (既定 8765)、静的配信は gui/static/、REPO は server.py の2階層上
- subprocess.run(timeout=30)。失敗は {"ok":false,"error":str} + 400/500

## API 契約 (新。フロントは別カードがこれだけを頼りに実装)
- GET /api/status → {"deps":{"herdr":bool,"claude":bool,"codex":bool,"python3":true},
  "install":{"cli":bool,"skill":bool},"repo":"<REPO絶対パス>","herdr_env":bool}
  - deps は shutil.which。install.cli は which("kanban") または ~/.local/bin/kanban が存在。
    install.skill は ~/.claude/skills/kanban-dispatch/SKILL.md が存在
- POST /api/install/cli → os.makedirs(~/.local/bin, exist_ok=True) し、~/.local/bin/kanban を
  REPO/kanban.sh へのシンボリックリンクに置き換え (既存リンクは付け替え、通常ファイルなら 400)。
  → {"ok":true,"in_path": "~/.local/bin" が PATH に含まれるか}
- POST /api/install/skill {"force":bool 省略可} → ~/.claude/skills/kanban-dispatch/SKILL.md を生成。
  既存かつ force でなければ {"ok":false,"error":"already installed (force で上書き)"} と 409。
  内容は次のとおり (REPO は絶対パスで埋め込む):
  ---
  name: kanban-dispatch
  description: "File-based kanban dispatch: card every implementation request and run the background dispatcher. Use when assigned implementation work in a project with .kanban/, or when asked to set up or operate kanban dispatch."
  user_invocable: true
  ---
  # kanban-dispatch
  The kanban CLI and the full workflow contract live in <REPO>.
  **Read <REPO>/README.md and follow it** (Secretary Bootstrap, Dialogue-Agent Contract, Model Policy, Herdr Integration).
  → {"ok":true,"path":"<書いた絶対パス>"}
- 設定 ~/.config/mornkanban/gui.json = {"projects":[...]} (既存仕様のまま)
- GET /api/projects → {"projects":[{"path","name","has_kanban"}]} (実在しないものは除外)
- POST /api/projects {"path"} → 実在ディレクトリのみ追加 → {"ok":true,"project":{...}}
- POST /api/init {"path"} → ["bash", REPO+"/kanban.sh", "init", path] → {"ok":true}
- 上記以外の /api/* は 404
