## Task

# 不具合
visible Herdr reviewer起動/待機時の `agent_not_found`、pane消失、wrapper通信失敗、review出力取得失敗等が、実装品質と無関係なのに `score: 0` としてworker attemptを消費する。最大attempt直前に起きると、完成済み成果がfailedになり、workerが長時間の実装・testを最初から繰り返す。

実例: card `20260831-233324-28344` は実装と156testを完了したが、最終reviewerが `agent target reviewer-56360-23575 not found` で消失し、0点→gave upになった。

# 期待動作
- review内容の低評価とreview infrastructure failureを別classとして扱う。
- `agent_not_found`、pane/process早期消失、timeout、wrapper protocol error、空answer、tool error JSON等はscoreへ変換せず `review infrastructure error` と判定する。
- infrastructure errorではworker attempt/rework countを消費せず、同じworktree・同じ成果commitのままreviewerだけを再起動する。workerを再実行しない。
- reviewer infra retry countを独立管理し、短いbounded backoffで再試行する。project policy/frontmatter/envで上限を設定可能にし、defaultは合理的な2〜3回。
- infra retry上限を超えたら成果をfailed扱いせず、`blocked`または専用の明確な状態へ移す。branch/worktree/commitを保持し、Historyへerror category、retry数、復旧commandを記録する。
- unparseable JSONでも、実際のreview本文からJSON抽出可能か、wrapper/tool errorかを区別する。別cardの出力やterminal status lineをscoreとしてparseしない。
- reviewer再接続後に正常JSONを得た場合だけthreshold判定する。
- worker/resolverの同種agent lifecycle errorにも同じ分類原則を適用し、実装失敗とinfrastructure failureを混同しない。

# visible Herdr lifecycle
- pane生成後のagent registration確認、agent target存在確認、answer file ownership/card id確認を行う。
- pane cleanup raceでanswer読取前にtargetを失わないよう順序を修正する。
- `.kanban-answer.md`はcard/worktree/role/attemptを照合し、stale/別card内容を拒否する。
- project固有secretary名、worker/reviewer/resolver、Claude/Codex、unrestricted permission policyを維持する。
- headless fallbackは禁止。

# 表示
- Card Historyとmonitorへ、quality review attemptとinfra retryを別々に表示する。
- `review infrastructure retry 1/3: agent_not_found` のように、秘密値を含めず原因を示す。
- blocked時はユーザーへ「コード不合格ではなくreview基盤停止」と通知する。

- infra errorがworker attemptsを増やさずrework instructionを付けないことを検証する。
- infra上限超過でblocked・branch保持・復旧可能になることを検証する。

- 空answer、status line、tool error JSON、malformed review JSON、stale別card answerを分類testする。
