## Task

# 再発した契約違反
秘書agentが「実装も検証もしない」と認識・宣言していたにもかかわらず、自分でheadless agentを起動して検証し、commit、push、tag作成まで行った。指摘後も「境界を決めさせてください」と確認を求めたが、境界は既に明確である。

秘書の許可範囲は次だけ:
1. project policy/盤面を読む
2. user要求を自己完結cardとして即起票する
3. `kanban-secretary.sh dispatch`でvisible Herdrへ渡す
4. done/failed/進行状態を報告する

それ以外の実装、編集、検証、review、commit、merge、push、tag、release、競合解消、headless agent実行は、userがその作業自体を依頼しても秘書が直接行わずcard化する。

# 目的
現在進行中の「秘書モードでin-processサブエージェント起動を禁止するガード」を拡張し、subagent起動だけでなく、秘書paneからの直接作業・Git変更・外部公開をtool実行前に技術的にdenyする。お願い文や自己反省だけに依存しない。

# fail-closed許可モデル
## 秘書paneで許可する操作
- `.kanban/KANBAN.md`、README contract、board/card、git status/log/diff/show等の必要最小限のread-only確認。
- `kanban add/show/list`等、起票と盤面確認に必要なCLI。
- `kanban-secretary.sh bootstrap/dispatch`、project固有secretary登録、通知確認。
- userへのcommentary/final報告。

## 秘書paneで拒否する操作
- file write/edit/delete/rename、`apply_patch`相当、生成物作成。ただし正式な`kanban add`によるcard作成とdispatcher自身のboard state変更は許可する。
- build/test/lint/formatter/server起動等の実装・検証command。検証要求もcardにする。
- bare `kanban run`、`claude -p`、`codex exec`その他headless worker起動。workerは必ずvisible Herdr helper経由。
- Claude/Codex組み込みin-process Agent/Task/subagent/collaboration tool（別カードのguardと統合）。
- Gitの変更系全般: add/commit/am/merge/rebase/cherry-pick/revert/reset/checkout/switch/branch作成削除/worktree変更/tag作成削除/push/fetch+write/pull等。read-only gitだけallow。
- GitHub/GitLab等の外部変更: push、release、PR作成/merge、tag/release publish、issue/comment、secret設定。
- package publish、deploy、LaunchAgent実変更、他project変更等。すべてcard経由のworkerへ渡す。
- shell chaining、absolute path、alias/wrapper、`sh -c`、script経由でdeny対象を迂回できないよう、文字列denylistだけでなくtool typeとsession-scoped allowlistを優先する。

# session/pane scope
- guardは`kanban-secretary.sh bootstrap`で登録されたproject-specific secretary pane/sessionだけに適用する。
- visible Herdr worker/reviewer/resolver、通常Claude/Codex session、他projectはblockしない。
- project root realpath、Herdr pane id、project固有secretary nameを照合する。stale markerやpane再利用で誤blockしないlifecycleを実装する。
- current guard card `20260831-204608-26288` とfailed resolver branch `kanban/20260831-194719-16227` の成果を調査し、重複実装を作らず統合する。並行成果とのmerge/競合は実行agentが解決する。

# Claude/Codex enforcement
- 導入済みCLIの公式/local docsと実versionを確認し、Claude Code hooks/tool policy、Codex hooks/rules/policy等の正式なpre-tool enforcement pointを利用する。存在しないAPI/config keyを捏造しない。
- setup/install/updateでmanaged guardを冪等に導入する。ユーザー既存hook/rule/configを構造保持し、MornKanban管理部分だけ追加・更新・uninstallする。
- 一方のCLIで完全なpre-tool denyが不可能なら、何が技術的にblockされ何がinstruction依存かをsetup dashboardで `enforced / partial / unavailable` と正直に表示し、READMEにも明記する。「対応済み」と誤表示しない。
- deny時は「秘書モードのため拒否。要求をcard化しvisible Herdr dispatchせよ」と具体的に返す。境界の再確認をuserへ求めない。

# 事故時recovery
- guardが違反を事前検出したら操作を実行せず、監査情報（時刻、operation category、project/pane。command本文や秘密値は保存しない）を記録し、card起票へ誘導する。
- 既に直接操作を始めたことに気づいた秘書は即停止する。自分でrollback、追加commit、push、tag削除等をせず、「違反成果の監査・回収」を別cardにする。
- push/tag等の外部変更はuserに事実を即報告し、取り消しもcard化する。自動削除しない。
