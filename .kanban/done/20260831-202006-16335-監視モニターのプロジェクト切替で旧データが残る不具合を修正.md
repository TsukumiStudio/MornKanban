## Task

# 不具合
`kanban monitor` のWeb UIでプロジェクトを選択・切り替えた直後、新しいプロジェクトのデータ取得が完了するまで、以前選択していたプロジェクトの盤面・カード情報が表示されたままになる。読み込みにラグがあると、現在どのプロジェクトを見ているのか誤認する。

また、短時間にA→B→A等と切り替えた場合、古い非同期レスポンスが後から返り、現在選択中とは異なるプロジェクトの内容を上書き表示するrace conditionも起こり得る。現在mainのmonitor実装を調査して両方を修正する。

# 期待動作
- プロジェクトを選択した瞬間、前プロジェクトのKanban列、カード詳細、履歴、件数などプロジェクト固有表示を即座にclearする。
- 新しいデータが届くまでは、選択したプロジェクト名と明確なloading/skeleton状態だけを表示する。旧データをloading背景に残さない。
- fetch失敗時は旧データへ戻さず、選択中プロジェクトに対するerror/再読み込み可能な状態を表示する。
- AbortControllerまたはrequest generation/token等を用い、選択変更前に開始したfetch/pollのレスポンスが現在表示を上書きしないようにする。
- 定期polling、手動更新、カード詳細取得にも同じ選択identityを適用する。プロジェクト切替後に旧プロジェクトのカード詳細が復活しないこと。
- URL/hash/history等で選択状態を持つ場合も、表示中データと選択project slugが常に一致すること。
- monitorは引き続き読み取り専用。書き込みAPI、操作ボタン、指示機能は追加しない。

# UI
- loading/error/empty/loadedを明確に区別し、レイアウトの大きな跳ねを抑える。
- 既存デザインとレスポンシブ表示を維持する。
- innerHTMLで未信頼文字列を挿入せず、既存のXSS防止境界を維持する。

# テストと完了条件
- フロントの状態遷移をテスト可能な形にし、少なくとも以下を自動検証する:
  1. A表示中にBを選ぶと同期的にAの列/詳細が消えloadingになる。
  2. Aの遅延レスポンスがB選択後に返ってもB画面を上書きしない。
  3. A→B→Aの高速切替で最後のAだけが表示される。
  4. 選択中projectの取得失敗時に旧projectデータが出ずerrorになる。
  5. pollingとカード詳細fetchでもstale responseを無視する。
- 必要に応じてNodeを使わない既存方針に合わせたJSテスト、またはブラウザ不要の状態管理テストを追加する。通常ワーカーなのでブラウザ自動操作は使わない。
- monitor API/GET-HEAD限定/path traversal拒否を含む既存Pythonテストと全リポジトリテストを再実行する。
- `node --check monitor/static/app.js`（実ファイル位置に合わせる）、関連Pythonの `python3 -m py_compile`、shellの `bash -n` を通す。
- README/VERIFY等に手動確認手順がある場合は、プロジェクト切替時のloading/race確認を追記する。
- VERSIONを規約に従って更新し、日本語コミットメッセージでコミットする。pushはしない。
