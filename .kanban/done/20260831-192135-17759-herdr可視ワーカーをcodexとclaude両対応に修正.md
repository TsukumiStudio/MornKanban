### 再現済みの事実

- `kanban-secretary.sh dispatch` は `KANBAN_WORKER_CMD` と `KANBAN_REVIEW_CMD` を
  `herdr-agent-worker.sh` で上書きする。
- `kanban.sh` はカスタム worker に `KANBAN_CARD_BACKEND` と `KANBAN_CARD_MODEL` を渡す。
- 現在の `herdr-agent-worker.sh` は `KANBAN_CARD_BACKEND` を読まず、常に
  `herdr agent start ... --kind claude ... --model "$model"` を実行する。

- reviewer も Claude 固定のため同様に止まり、端末表示が非 JSON として採取されて 0 点、
  `max_attempts: 3` まで同じ失敗を繰り返した。
- 裸の `kanban run` では Codex backend が正しく使われるため、問題は可視 Herdr 経路に限定される。

### 実装要件

1. `herdr-agent-worker.sh` が役割別に backend を決定する。
   - worker: `KANBAN_CARD_BACKEND`
   - reviewer: `KANBAN_REVIEWER`
   - `auto` は `KANBAN_BACKEND_ORDER` の先頭から、利用可能な CLI を選ぶ。通常の
     `kanban.sh` の解決規則と一致させる。
   - `claude` / `codex` 以外、または利用可能な backend がない場合は、pane を増やす前に
     backend 名を含む明確なエラーで停止する。
2. 解決した backend を `herdr agent start --kind` に使う。
   - Claude: `--kind claude`、worker は `--permission-mode acceptEdits`、モデル未指定時は
     `sonnet`。reviewer は既存の read-only 運用を壊さない。`KANBAN_ALLOWED_TOOLS` は
     Claude 引数としてのみ渡す。
   - Codex: `--kind codex`、worker は `-s ${KANBAN_CODEX_SANDBOX:-workspace-write}` と
     `-a never`、reviewer は `-s read-only -a never`。モデルが空なら Codex 自身の既定を使い、
     `sonnet` を補わない。モデル指定時だけ `-m <model>` を渡す。
   - Claude 専用引数を Codex に、Codex 専用引数を Claude に渡さない。
3. folder trust 対応、prompt、permission 待機、`.kanban-answer.md` 回収・削除、pane cleanup、
   ラベル表示、browser role の排他方針は維持する。Codex の alternate screen でも最終回答
   ファイルを正として回収できる構成を保つ。
4. reviewer backend がカスタム review command に確実に伝わるか `kanban.sh` も確認し、
   `KANBAN_REVIEWER` だけで不十分なら最小限の明示的な環境変数受け渡しを追加する。
5. `tests/test_kanban_secretary.py` に fake Herdr を用いた回帰テストを追加する。少なくとも以下を
   実際の `herdr agent start` ログで検証する。
   - Claude worker + sonnet は `--kind claude` と Claude 引数だけ。
   - Codex worker + `gpt-5.6-terra` は `--kind codex`、Codex sandbox/approval/model 引数だけ。
   - Codex reviewer は `--kind codex`、read-only、指定 review model。
   - Codex model 未指定時に `sonnet` や空の `-m` を渡さない。
   - `auto` と不正 backend の成功・失敗条件。検査対象が0件でも成功するテストにしない。
6. 回帰テスト作成後、コピー上で `--kind claude` 固定へ意図的に戻し、Codex テストが今回と
   同じ理由で失敗することを確認する。元へ戻して全テストを再度通す。
7. `README.md`、スクリプトコメント、配布スキル内にある「可視 worker は Claude 固定」という
   全記述を `rg` で列挙し、backend-aware な実態へ更新する。同種の古い主張を残さない。
8. 現在の VERSION / 更新ポリシーを確認し、配布挙動の修正として必要なら patch version を上げる。
