## Task

# 目的
単純な「なぜ遅いか調査」に、実装・3回benchmark・mutation・monitor UIまで詰め込み39分化した。秘書の起票contractを修正し、調査要求を過大cardにしない。

# 契約
- 調査/診断cardは原則5分目標・最大10分のread-only分析と証拠報告に限定する。
- 修正は診断結果後の別card。ユーザーが明示的に同時修正を求めた場合だけ実装を含める。
- 一cardは一成果・一主要責務。completion conditionは必須だが、関連し得る改善を網羅的に追加しない。
- workerがtimebox超過見込みなら途中成果をanswer/Historyへ書き、`BLOCKED: scope/timebox`で戻す。黙って長時間継続しない。
- 秘書はcardを即起票するが、巨大化させず小さく分ける。順序/競合解決は実行側の責務のまま。
- source/installed kanban-dispatch skill、README、生成KANBAN.md templateへ反映する。

# テスト
- contract testでdiagnose-only、5/10分timebox、実装別card、過剰completion禁止を固定する。
- worker promptにdeadline/expected outputが入ることを確認する。
- docs/contract変更中心。targeted testとskill validation、fast suite各1回。日本語commit、pushなし。
