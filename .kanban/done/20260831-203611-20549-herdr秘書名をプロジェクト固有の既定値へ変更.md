## Task

# 不具合・背景
現在のvisible Herdr連携は秘書エージェント名の既定値が全project共通の `secretary` であるため、複数projectでMornKanban秘書を同時利用すると名前が衝突する。実例として、別projectで既定名が使用中だったため `secretary-kimekyawa` を手動採用し、以後のdispatchも同名へ合わせる必要が生じた。

全project共通の固定既定値を廃止し、projectごとに安定した固有名を自動決定する。対話agentが毎回空き名を考えたり、bootstrapとdispatchで手動同期したりしなくてよい設計にする。

# 必須仕様
## project固有default
- `secretary` 単独をdefaultにしない。project identityから、人間にも分かる名前を自動生成する。基本形は `secretary-<project-slug>`（例: `secretary-kimekyawa`）。
- project slugは、PC共通project registryにaliasがあればそれを優先し、なければrepository/project root basenameを安全にslug化する等、既存機能と一貫する規則にする。
- 同名directory、Unicode、空/記号だけ、長すぎる名前でもHerdr agent名として有効かつ衝突しないよう、必要な場合だけ短い安定hashを付与する。単純なランダムsuffixにはせず、同じprojectで再bootstrapしても同じ名前になること。
- project rootのrealpathをidentityに使い、subdirectoryからbootstrap/dispatchしても同じ名前になること。`.kanban/wt`内を別project扱いしない。

## 設定と優先順位
- 明示overrideをproject policyで設定可能にする。frontmatter例 `secretary_agent: secretary-kimekyawa` 等を正式化し、既存 `KANBAN_HERDR_SECRETARY` 環境変数との優先順位を `environment > .kanban/KANBAN.md > generated project default` とする。
- override値もHerdr名としてvalidateし、不正値は黙って別名にせず明確に失敗・案内する。
- bootstrap時に決定した名前を表示し、登録・通知先・dispatcherへ同じ値を確実に渡す。必要なruntime stateを保存する場合はproject-local `.kanban`内でatomicに扱い、stale session情報を安全に更新する。

## 全経路の整合
- `kanban-secretary.sh bootstrap`、`dispatch`、`herdr-notify-secretary.sh`、worker/reviewer/resolver hook、installed `kanban-dispatch` skillがすべて同じ名前解決関数/値を使う。
- notifyが誤って別projectの `secretary` や他project固有秘書へ送られないこと。
- 複数projectのdispatcherを同時起動しても、それぞれの秘書へdone/failed通知が届くこと。
- 旧環境で明示的に `KANBAN_HERDR_SECRETARY=secretary` を設定している利用者はoverrideとして互換維持する。ただし未設定の新defaultはproject固有名にする。
- 既存のvisible Herdr必須・headless silent fallback禁止・focus維持・pane cleanupを壊さない。

# UX・文書
- bootstrap完了メッセージに `secretary=<resolved-name>` を含める。
- name collisionがHerdr側で検出された場合、project identityと候補名を示し、policy override方法を案内する。別projectの稼働agentを上書き/奪取しない。

## 変更内容

全project共通の固定既定秘書名 `secretary` を廃止し、`secretary-<project-slug>` をprojectごとに決定論的に生成するようにした。

- `registry/secretary.py` (新規): 純粋なロジック。
  - `default_slug(root)`: PC共通project registryにこのrootのaliasがあればそれを優先、なければrootのbasenameをslugify。Unicode/空/記号だけ/長すぎる場合のみ `root` のsha256先頭6桁を安定hashとして付与。同じbasenameの別pathは意図的に同じ既定名になる (衝突はHerdr登録時に検出させる設計)。
  - `resolve(root, env_override)`: 優先順位 `environment > .kanban/KANBAN.md の secretary_agent: > 生成デフォルト`。不正なoverride値 (`^[a-z][a-z0-9_-]{0,63}$` に非適合) は `SecretaryNameError` で明確に失敗。
- `registry/cli.py`: `secretary resolve <root>` サブコマンドを追加 (JSON `{name, source, root}` を出力)。
- `kanban-root.sh` (新規、bash source用共有関数): `kanban_project_root()`。`.kanban/wt/<id>` worktree内から呼ばれても `/.kanban/wt/` 以降を剥がしてから探索するため、外側のproject rootに正しく解決する (worktreeが自分自身の `.kanban/{todo,doing,...}` を tracked ファイルとして持つため、素朴な上方探索は誤ってworktree自体をrootと誤認する不具合があった)。
- `kanban-secretary.sh`: 旧 `SECRETARY_NAME=${KANBAN_HERDR_SECRETARY:-secretary}` を削除し、root確定後に `resolve_secretary_name` (python resolver呼び出し) で名前を決定。bootstrap完了メッセージに `secretary=<resolved-name>` を含め、`herdr agent rename` 失敗時はproject identity・候補名・override方法 (`KANBAN_HERDR_SECRETARY=<name>` または `KANBAN.md` の `secretary_agent:`) を案内して失敗させ、他projectの稼働agentは奪わない。dispatchも同じ解決を行い、`KANBAN_HERDR_SECRETARY` として起動するdispatcherパネへ確実に伝播する。
- `herdr-notify-secretary.sh`: `KANBAN_HERDR_SECRETARY` 未設定時のフォールバックを固定 `secretary` から、`$PWD` のproject rootに対する同じresolverの結果へ変更。
- `kanban.sh`: `cmd_init` のKANBAN.mdテンプレートに `secretary_agent:` (コメントアウト例) と説明セクションを追加。
- `README.md`: 「Secretary agent naming」節を新設し、優先順位・衝突時の挙動・A/B 2project同時運用例を記載。Configuration表・KANBAN.md frontmatterの説明も更新。
- `skills/kanban-dispatch/SKILL.md`: bootstrap結果の `secretary=` 名を報告に含める指示、および衝突失敗時にそのまま報告し勝手に別名を選ばない指示を追加。
- `VERSION`: `0.3.1` → `0.4.0`。
